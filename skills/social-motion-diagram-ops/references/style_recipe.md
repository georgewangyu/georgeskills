# Style Recipe

## Core Pattern

The useful pattern is not "make a GIF." It is:

1. A dense static diagram explains the system.
2. A tiny motion layer shows the path through the system.
3. The post text then names the takeaway.

The visual should still work as a still image. Motion is there to guide attention, not to carry the whole explanation.

## Visual Ingredients

- Canvas: near-square or landscape, with enough whitespace around the diagram for social crops.
- Background: white or warm off-white.
- Linework: dark gray, 1.5-3 px, slightly informal if the renderer supports it.
- Type: friendly handwritten or rounded sans if available; otherwise clean sans with medium weight.
- Color: 2-4 accents max. Use green/teal for flow or "done", purple/pink for policy/check layers, blue for cognitive/core components, orange only for contrast/warning.
- Icons: simple line icons; use familiar symbols for schedule, message, database, memory, checker, output, tools.
- Text: short labels inside boxes; explanatory detail belongs in the post, not the diagram.

## Motion Ingredients

- One moving dot along arrows is usually enough.
- Secondary motion can be a brief glow, checkmark, spinner, or icon swap.
- Do not animate every object. Too much motion makes the diagram harder to read.
- Favor constant, calm motion over bounce-heavy animation.
- Loop duration: 1.5-4 seconds.
- Frame rate: 12-24 fps for diagram motion.

## Good Social Diagram Shapes

- Manual vs self-running loop.
- Maker/checker split.
- Agent core surrounded by memory, tools, safety, and state.
- Request → plan → act → observe → verify → update state.
- Draft → visual claim → diagram → motion path → rendered asset.

## Quality Bar

Before finishing, check:

- Can someone understand the main claim in under three seconds?
- Is there one obvious path for the eye to follow?
- Does the poster frame look good without motion?
- Are all labels readable on mobile?
- Is the visual distinct from the referenced inspiration rather than a clone?
